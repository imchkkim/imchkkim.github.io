4. Actor-Critic — 비평가를 곁에 두다

GAE: 둘 사이를 λ로 잇는다

MC는 치우침이 없는 대신 분산이 크고, TD는 분산이 작은 대신 비평가가 틀린 만큼 치우친다. 둘 중 하나만 골라야 할까? 가까운 미래는 실제 결과를 보고 먼 미래만 비평가에 맡기는 중간은 없을까?

역사: 버클리의 절충

이 중간을 한 개의 손잡이로 만든 것이 UC 버클리의 존 슐먼(John Schulman)과 동료들(Moritz, Levine, Jordan, Abbeel)이 2016년 ICLR에 발표한 GAE다. 원래 목표는 로봇 보행 같은 연속 제어였지만, 같은 슐먼이 이듬해 내놓은 PPO와 짝을 이루며 언어모델 RLHF의 기본 부품이 됐다.

λ로 더하는 TD 오차

GAE(Generalized Advantage Estimation)는 두 극단 사이를 연속적으로 잇는다. TD 오차를 앞으로 쭉 더하되, 멀어질수록 λ\lambdaλ배씩 줄인다.

중간의 λ\textcolor{#993600}{\lambda}λ는 "가까운 미래는 실제 결과를 보고, 먼 미래는 비평가를 믿는다"는 절충이다.

위젯에서 해볼 것:

  • 오답 응답, 비평가 완벽에서 λ\textcolor{#993600}{\lambda}λ를 1 → 0으로 내려 보라. λ=1\textcolor{#993600}{\lambda} = 1λ=1에서는 모든 토큰이 벌을 받지만, λ=0\textcolor{#993600}{\lambda} = 0λ=0에서는 "24"에만 큰 음수가 몰리고 "10 × 3"은 오히려 상을 받는다.
  • 비평가 오차를 올리고 다시 λ=0\textcolor{#993600}{\lambda} = 0λ=0을 보라. 마름모(진짜 기여도)와 막대가 어긋난다. λ=1\textcolor{#993600}{\lambda} = 1λ=1 쪽은 비평가 오차에 훨씬 덜 흔들린다.
ML에서: 언어모델의 기본값

언어모델 RLHF의 흔한 기본값은 γ=1\textcolor{#536020}{\gamma} = 1γ=1, λ=0.95\textcolor{#993600}{\lambda} = 0.95λ=0.95다. 보상이 응답 끝에 한 번만 오므로 할인할 이유가 없고, λ\textcolor{#993600}{\lambda}λ 는 1 쪽에 두어 학습 초기의 부정확한 비평가에 덜 기댄다. 비평가를 학습할 때의 목표값도 보통 이 GAE 어드밴티지에 가치를 더한 G^t=A^t+Vϕ(st)\textcolor{#0033ff}{\hat G_t} = \textcolor{#8e44ad}{\hat A_t} + \textcolor{#00897b}{V_\phi}(\textcolor{#0093b8}{s_t})G^t​=A^t​+Vϕ​(st​)(λ\textcolor{#993600}{\lambda}λ-리턴: GAE로 섞어 만든 '앞으로 받을 점수’의 추정)를 쓴다. 앞 절 회귀 손실의 G^t\textcolor{#0033ff}{\hat G_t}G^t​ 가 바로 이것이다.

문제 2 — 망원경처럼 접히는 합

γ=1\textcolor{#536020}{\gamma} = 1γ=1, λ=1\textcolor{#993600}{\lambda} = 1λ=1일 때 GAE가 R−V(st)\textcolor{#d9670b}{R} - \textcolor{#00897b}{V}(\textcolor{#0093b8}{s_t})R−V(st​)가 됨을 보이시오. 정답 응답(R = 1, 표의 가치들)의 첫 토큰으로 수치를 확인하시오.

코드로 해봤어요. λ=1이면 δ를 전부 더하는 거니까, 첫 토큰부터 끝까지 δ를 더하면… 0.55가 나와요. R − V(s₀) = 1 − 0.45 = 0.55랑 같네요.
식으로도 보일 수 있어요?
더하면 V(s₁) − V(s₀) + V(s₂) − V(s₁) + … 이렇게 가운데가 지워지고, 마지막에 V(s_T) − V(s₀)이 남아요. 그러니까 V(s_T) − V(s₀)… 어? R이 어디 갔지?
마지막 δ에는 보상 r이 들어 있잖아. 그리고 V(s_T)는 응답이 끝난 뒤의 상태라서, 더 받을 보상이 없으니까 0이야.
아, 종료 상태 가치를 0으로 안 두고 비평가 출력을 그대로 넣었어요. 코드에서는 마지막에 R을 따로 더해서 우연히 맞았네요.
실무 코드에서 아주 흔한 버그예요. 응답이 최대 길이에서 잘렸을 때는 “끝난” 게 아니라 “중단된” 거라 V(s_T)를 0으로 두면 안 되고요. 이 구분 때문에 DAPO 같은 방법은 잘린 응답을 따로 처리해요.
보고서 쓸 때 마감 시간 되어서 멈춘 거랑, 다 쓰고 끝낸 거랑 채점이 다른 거네요.
