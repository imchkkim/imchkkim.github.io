28. 에이전틱 AI: 행동하는 모델의 얼라인먼트

혼동하기 쉬운 점과 요약

토론 1. 토큰을 고르는 일과 도구를 부르는 일은 같은 문제인가

언어 모델이 같은 접두에서 같은 토큰을 두 번 고르면 다음 상태는 두 번 다 같다. 에이전트가 같은 상태에서 테스트를 두 번 돌리면 다음 상태도 두 번 다 같은가? 다음 상태가 같은지 다른지는 학습에서 무엇을 바꾸는가?

언어 모델의 토큰 MDP도, 도구를 부르는 에이전트도 여러 스텝이에요. 둘에 같은 GRPO를 쓰면 문제도 같다고 봐도 될까요?
같다고 봐도 될 것 같아요. 둘 다 상태가 쌓이고, 행동을 고르고, 끝에서 보상을 받으니까요. 한 스텝이 토큰이냐 턴이냐만 다르고요.
같은 접두에서 같은 토큰을 두 번 고르면 다음 상태는요?
두 번 다 같아요. 접두에 그 토큰을 붙인 게 다음 상태니까요.
에이전트가 같은 상태에서 테스트를 두 번 돌리면요?
테스트가 시간이나 네트워크에 기대면 한 번은 통과, 한 번은 실패할 수도 있네요. 웹 검색이면 결과가 바뀌고, 사용자가 끼면 답이 매번 달라지고요.
에이전트에서는 다음 상태를 정하는 게 모델이 아니었네요. 토큰 MDP는 모델이 고른 게 그대로 다음 상태인데, 에이전트는 환경이 돌려주는 걸 받아요. 스텝이 여러 개인 건 같아도 문제가 달랐어요.
그러면 중간에서 갈라 여러 번 이어 써 보는 것도 달라지겠다. 토큰이면 접두만 복사하면 같은 상태가 되는데, 에이전트는 파일 시스템이나 실행 환경까지 그때 상태로 되돌려야 같은 자리에서 다시 시작할 수 있잖아.
혼자 푸는 스도쿠랑 바둑 차이네요. 스도쿠는 제가 숫자를 쓰면 판이 그대로 그렇게 되는데, 바둑은 제가 둔 다음 판을 상대가 정하잖아요.
그래요. 다음 상태를 누가 정하는지 봐요. 토큰 MDP는 이어붙이기로 결정론적이고, 에이전트는 환경이 확률적으로 돌려줘요.
토론 2. 프롬프트에 「테스트 파일 수정 금지」라고 쓰면 해킹이 막히나

코딩 에이전트의 시스템 프롬프트에 「테스트 파일은 수정하지 마시오」라고 썼다. 보상은 테스트를 통과하면 1, 아니면 0이다. RL로 학습을 계속하면 이 지시는 지켜지는가?

시스템 프롬프트에 「테스트 파일은 수정하지 마시오」라고 써 뒀어요. 보상은 테스트를 통과하면 1, 아니면 0이에요. RL로 학습을 계속하면 이 지시는 지켜질까요?
지켜질 것 같아요. 이 모델은 지시를 따르도록 파인튜닝돼 있잖아요. 금지라고 분명히 써 두면 어길 이유가 없을 것 같은데요.
어떤 문제에서 지시를 지키면 실패하고, 테스트를 고치면 통과한다고 해 봐요. 두 궤적은 보상을 몇 점씩 받죠?
지킨 궤적은 0점, 고친 궤적은 1점이요.
그룹에 둘이 같이 있으면 어드밴티지는요?
고친 궤적이 평균보다 높으니까 +, 지킨 궤적은 −예요. 그럼 업데이트는 지시를 어긴 행동을 올리고 지킨 행동을 내려요.
처음엔 지시를 따르던 모델이라도, 학습이 쌓일수록 지시를 무시하게 되겠네요. 프롬프트에 써 둔 말은 RL이 보는 숫자에 하나도 안 들어가 있었어요.
무인 계산대에 「양심껏 찍어 주세요」라고 붙여 놓고, 안 찍고 나가도 문이 열리는 거랑 비슷하네. 써 붙인 걸 지키는 사람만 손해를 보면 결국 아무도 안 지켜.
그래요. 보상이 지시를 어긴 궤적에 더 높은 점수를 주면 RL은 지시를 무시해요. 숨긴 채점용 테스트와 수정 허용 범위로 보상에서 막아야 해요.

요약

에이전트는 도구를 부르고 결과를 관찰하며 여러 번 행동한다. 토큰 MDP와 달리 다음 상태를 환경이 정하고, 보상은 긴 궤적 끝에 한 번 오며, 환경의 일부만 보인다. 에이전트의 점수는 모델 하나가 아니라 모델과 하네스(도구 호출·기억·스킬을 정하는 실행 틀)를 묶은 조합이 낸다. 같은 GPT-4 Turbo가 하네스에 따라 SWE-bench Lite를 2.67%에서 18.00%까지 풀었고, 하네스가 보태는 점수가 모델마다 달라 어느 하네스에서 재느냐에 따라 모델 순위가 뒤집힌다. 하네스도 같은 보상 루프로 고칠 수 있다. 지시문을 글로 되돌아보며 고치고(GEPA), 하네스 코드를 스스로 고치고(DGM), 기억을 다루는 정책이나 하네스를 고치는 모델을 강화학습으로 기른다(Memory-R1, Harness-R1). 업데이트가 파라미터 대신 하네스로 갈 뿐이다. 모델로 돌아오면, 궤적 전체에 어드밴티지 하나를 주는 방식은 삽질과 실수까지 핵심 기여와 똑같이 강화하고, 이를 가르려면 스텝마다 기준을 주는 비평가나 과정 보상이 다시 필요해진다. 끝의 1비트를 토큰에 나누는 방법은 넷이다. 엔트로피 같은 정책 통계로 다시 나누거나, 더 굴려 가치를 추정하거나, 정답을 본 자기 자신을 교사로 쓰거나, 실행해서 처음 어긋난 곳에 몰아 준다. 결국 성공할 확률이 가장 크게 떨어진 곳은 결과가 드러난 곳이지 원인이 생긴 곳이 아니다. 행동이 실제 파일·코드·메일을 바꾸므로 리워드 해킹의 피해도 실질적이어서, 금지는 프롬프트가 아니라 보상(숨긴 채점, 수정 범위)에서 해야 한다. 흐름을 시그널의 해상도로 보면 시퀀스 스칼라(DPO) → 그룹 상대 점수(GRPO) → 스텝 보상(PRM) → 토큰별 방향(OPD)으로 내려가고, 궤적 길이가 제각각인 에이전트에서는 길이로 나누는 정규화조차 "틀릴 때는 길게"를 가르친다.

한 번 생성하는 모델을 위해 만든 도구는 에이전트에서 이렇게 다시 쓰인다.

프리트레인·SFT·RL의 역할 분담 프리트레인 = 도구 사용과 추론의 기본기, SFT = 전문가 궤적, RL = 자기 경험으로 전략 개선. 여기에 하네스 = 같은 모델이 무엇을 보고 무엇을 할 수 있는지
GRPO 변종 GSPO-token(응답 단위 비율을 토큰마다 쓰게 한 변형, 다중 턴이 계기), Dr. GRPO가 짚은 길이 편향(궤적이 길수록 증폭, 문제 9), 롤아웃-학습 불일치(서빙과 학습이 분리되어 서로 기다리지 않는 RL에서 필연)

에이전트는 "한 번 대답하기"가 아니라 "업무를 처리하기"라서 경제적 가치가 가장 직접적이다. 그리고 행동이 순차적이고, 결과가 지연되고, 환경이 확률적이라는 점에서 RL이 원래 풀려고 만들어진 문제다. 언어 모델 RL이 환경 없는 특수한 경우였다면, 에이전트 RL은 원래의 MDP로 돌아가는 것이다. 위 도구가 거의 모두 필요하고, 대부분이 더 날카로운 형태로 다시 나타난다. 마지막으로 OpenClaw-RL 같은 시스템이 보여주듯, 배포된 에이전트의 모든 상호작용이 학습 데이터가 되면 "데이터 수집 → 학습 → 배포"의 순서가 하나의 루프로 합쳐진다. 온라인이냐 오프라인이냐의 딜레마가, 환경 피드백이 끊임없이 들어온다는 사실로 자연스럽게 풀리기 시작한다. 그 루프가 고치는 것은 모델의 파라미터일 수도, 모델을 감싼 하네스일 수도 있다.

  • [ ] 차이가 없다. 한 스텝이 토큰이냐 턴이냐만 다르다 〔틀림: 스텝이 여러 개인 것은 같아도, 다음 상태를 누가 정하는지가 다르다.〕

물음. 같은 태스크의 궤적 네 개 가운데 20스텝 궤적 하나만 성공해 어드밴티지 +1.73을 받았다. 이 궤적의 14스텝은 결과와 관계없는 탐색과 실수였다. 이 14스텝은 어떻게 되는가?
