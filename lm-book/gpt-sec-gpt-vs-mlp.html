멀리 보기: 200줄이 안 되는 GPT

MLP 와 같은 조건으로: 바이트당 비트 0.6129

GPT 가 좋다는 말은 많이 들었지만, 우리 데이터에서 얼마나 좋은지는 같은 조건으로 학습해 봐야 안다. 조건이 다르면 차이가 모델에서 왔는지 학습량에서 왔는지 가를 수 없다. 그래서 MLP 언어 모델과 같은 토크나이저(BPE 4,096), 같은 4,000 스텝, 같은 스텝당 16,384 토큰으로 학습하고, 같은 검증 글 전체에서 바이트당 비트를 측정한다. 학습률만 GPT 에 흔히 쓰는 2e-3 으로 두었다.

# sources/gpt/train_gpt_small.py 에서 발췌
cfg = GPTConfig(vocab_size=tok.vocab_size, block_size=256, n_layer=4, n_head=4, n_embd=256)
m = GPT(cfg).to(dev)
h = T.train(m, tr, va, tb, batch_size=64, block_size=256, max_steps=4000, lr=2e-3, warmup=100,
            grad_clip=1.0, eval_every=250, log_every=250, device=dev, eval_tokens=2_000_000)
full = T.evaluate(m, va, tb, 64, 256, len(va), dev)

## 3. 학습: 4,000 스텝, 배치 64 x 256 토큰, 학습률 2e-3 (예열 100 스텝 + 코사인), 그래디언트 자르기 1.0
eval step      0 | tokens 0 | val_loss 8.3832 | val_bpb 3.0421 | 0s
eval step    500 | tokens 8,192,000 | val_loss 2.4512 | val_bpb 0.8928 | 6s
eval step   1000 | tokens 16,384,000 | val_loss 2.1310 | val_bpb 0.7756 | 13s
eval step   2000 | tokens 32,768,000 | val_loss 1.8828 | val_bpb 0.6853 | 25s
eval step   3000 | tokens 49,152,000 | val_loss 1.7505 | val_bpb 0.6373 | 37s
eval step   4000 | tokens 65,536,000 | val_loss 1.6862 | val_bpb 0.6140 | 50s
검증 글 전체: 손실 1.6838, 바이트당 비트 0.6129, 학습 50초
같은 조건의 MLP 언어 모델(앞 6 토큰): 바이트당 비트 0.9326

학습 기록은 250 스텝마다 찍히는데 여기에는 500 스텝마다만 옮겼다. RTX 4090 한 장에서 50초 만에 바이트당 비트가 0.6129 가 되었다. MLP 의 0.9326 보다 바이트마다 0.32 비트를 덜 쓰니, 같은 검증 글을 적는 데 드는 비트가 2/3 쯤으로 줄었다. 학습한 토큰은 6,553만 개로 학습 글 5억 5,265만 토큰의 12% 가 조금 못 된다.

GPT 가 학습한 지 410만 토큰째(250 스텝)에 이미 1.0597 로, MLP 가 6,553만 토큰을 다 본 뒤의 0.9326 과 크게 다르지 않다. 그러면 GPT 가 앞서는 부분은 이야기의 어디에서 생길까? 학습한 두 모델을 검증 글 앞 200만 토큰에 걸고, 256 토큰 조각 안의 위치마다 손실을 따로 평균했다(sources/gpt/position_and_mask.py).

출력에서 위치 몇 줄을 줄였다. 볼 수 있는 토큰이 하나뿐인 위치 0 에서는 바로 앞 토큰 하나로 할 수 있는 일이 어느 모델이나 같아서, 두 모델의 손실이 3.79 로 같다. MLP 의 손실은 앞 여섯 토큰을 다 채운 뒤로 2.55 근처에서 더 내려가지 않는데, GPT 는 앞 16 토큰에서 1.97, 앞 64 토큰에서 1.66 까지 내려간 뒤 100 토큰쯤부터 1.6 정도에서 평평해진다. 문맥은 256 토큰까지 보이지만, 이 작은 모델이 손실을 줄이는 데 쓰는 문맥은 앞 100 토큰쯤까지다.

통하지 않은 길: 토크나이저 없이 바이트를 그대로 읽기

토크나이저를 정하던 날 서연은 오타 「Lnua」가 낯선 토큰 넷으로 갈라질 바에야 바이트를 그대로 읽히면 어떠냐고 물었는데, 이 GPT 의 어휘만 바이트 256 개와 이야기 시작 표시로 바꾸어 측정해 보았다. 스텝 수와 문맥 길이를 바꾼 세 번의 학습에서 바이트 GPT 의 검증 바이트당 비트는 0.70~0.90 으로, 토큰 GPT 의 0.6129 에 한 번도 미치지 못했다(같은 양의 글을 읽힌 판이 0.7000 이고 학습 시간은 세 배쯤 들었다, sources/tokens/byte_vs_bpe.out). 바이트를 읽는 모델이 토큰 모델을 따라잡았다는 보고(메타의 BLT, 2024)는 파라미터 80억, 학습 바이트 4조까지 키운 뒤의 일이라, 루나는 BPE 4,096 토큰으로 간다.

따라 하기 · 게이밍 GPU 한 장

토큰 파일과 MLP 언어 모델의 체크포인트를 만든 뒤(비교 줄을 찍으려면 MLP 를 먼저 학습해야 한다), 책 저장소에서 CUDA_VISIBLE_DEVICES=0 python -u sources/gpt/train_gpt_small.py > sources/gpt/train_gpt_small.out 을 돌린다. RTX 4090 한 장에서 53.0초(학습 50초)가 걸렸다. 위치마다의 손실과 마스크 없는 학습은 python -u sources/gpt/position_and_mask.py 로 13.7초, 역사 그림은 python sources/gpt/history_sizes.py 로 그린다.

따라 하기 · 노트북

같은 스크립트를 CPU 에서 돌리면 배치 64 × 256 으로 스텝당 6.036초, 4,000 스텝에 402.4분이 걸린다고 추정했다. train_gpt_small.py 의 T.train 에 준 batch_size=64, block_size=256 을 16, 128 로 줄이면 스텝당 1.750초, 4,000 스텝에 116.6분이다(sources/mlp-lm/cpu_timing.out, 이 머신의 CPU 를 스레드 4 개로 묶어 측정한 스텝 시간에 스텝 수를 곱한 추정이고 실제 노트북은 더 느릴 수 있다). 조각이 짧아지면 위치마다의 그림도 128 에서 끝난다.

문제 5. 차이는 어느 위치에서 왔나

위치마다의 손실 표에서 두 모델의 전체 평균 차이는 2.5669 − 1.6862 = 0.8807 nat 이다. 0.8807 nat 가운데 위치 32~255 에서 온 부분은 몇 % 인가? 그리고 두 모델이 같은 토큰들을 보는 위치 0~5 에서 GPT 가 0.058 nat 낮은 것은 볼 수 있는 문맥의 길이로 설명할 수 있는가?

구간마다 「차이 × 구간 길이 / 256」을 더하면 되겠다. 0~5 는 0.0578 × 6 / 256 = 0.0014, 6~31 은 0.5773 × 26 / 256 = 0.0586, 32~127 은 0.9081 × 96 / 256 = 0.3405, 128~255 는 0.9602 × 128 / 256 = 0.4801. 다 더하면 0.8806 이라 반올림까지 맞아.

그럼 위치 32 부터가 0.3405 + 0.4801 = 0.8206, 전체의 93% 네. 차이 대부분이 앞 32 토큰 넘게 볼 수 있는 자리에서 나왔어.

두 번째 물음은요?

위치 0~5 에서는 둘이 보는 토큰이 같으니까 문맥의 길이로는 설명할 수 없어요. 그 작은 차이는 큰 차이와 원인이 다른 거네요.

그래요. 위치 0~5 의 차이가 어디서 왔는지는 이 표로 가를 수 없고, 전체의 0.2% 도 안 되니 넘어가요. 큰 차이는 볼 수 있는 문맥이 길어지는 자리에서 나왔어요. 둘을 나눠 볼 수 있었던 건 위치마다 측정했기 때문이고, 평균 하나만 봤으면 「GPT 가 0.88 nat 낫다」로 끝났겠죠.
